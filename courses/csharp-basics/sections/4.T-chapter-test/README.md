# 4.T, Chapter 4 Test (region boss)

The Chapter 4 region boss. It combines everything from 4.1 to 4.6 (resting on Chapters 1 to 3) into realistic
decision scenarios. No new material is taught. Passing it lights the Chapter 4 region on the map.

## How it works
- **Pooled:** a single attempt draws **10** problems from the **20**-problem pool below. Passing **6** lights
  the region (~60%). A generous **24h** window; miss it or fall short and it simply does not light, a retry
  draws a fresh set. No lockouts, ever.
- **Non-memorizable, from both sides:** the pool is bigger than the draw, AND each pool problem takes stdin,
  so it carries several value-varied input cases. Memorizing one attempt's answers does not survive the next
  draw, and a single-branch answer cannot pass a problem's own varied cases.
- Source of truth: `test.yaml`. Each pool problem is an ordinary problem folder under `pool/`; expecteds are
  generated by the oracle CLI from each `solution.cs`.

## Scope (same boundary as Chapter 4)
- **Input is used:** values come in via stdin. Prompts are printed on their own line, and the prompt text is
  part of the graded output.
- **The full decision toolkit from this chapter:** booleans and comparisons (4.1), `if` (4.2), `if`/`else`
  and `else if` chains (4.3), combining with `&& || !` (4.4), nested conditionals (4.5), and `switch` (4.6),
  on top of types, input, parsing, interpolation, and arithmetic (`+ - * / %`) from Chapters 1 to 3.
- **No loops or methods** (Chapters 5 and 6). Output is `WriteLine` of a literal, a computed value, or a
  `bool`; the conditions decide which runs.
- Boolean inputs arrive as a `0`/`1` flag read as an `int` (no bool parsing yet).

## Anti-hardcoding: straddle every boundary
This is the decisions boss, so the per-problem rule is stronger than the earlier chapters' varied-input rule:
each problem's cases must reach **every block, every `case`, both sides of every condition, and every leaf of
a tree**. A memorized or single-branch answer fails. A branching program is deterministic per stdin, so the
oracle `gen`/`check` work unchanged; the cases are simply designed to cover the branches.
