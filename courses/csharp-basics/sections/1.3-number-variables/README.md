### The problem format (per problem folder), the key design decision
Each problem separates **language-independent design** from **C#-specific syntax**, so the same problem can be re-expressed in Java/Python/C++ cheaply (we author the thinking once, translate the syntax).

```
pNN-slug/
  design.md       ← LANGUAGE-INDEPENDENT: the idea, the statement, the I/O contract,
                    the test inputs + why (edge cases), the expected-logic. REUSED across languages.
  starter.cs      ← C#-specific: pre-seeded file the student edits
  problem.yaml    ← SOURCE OF TRUTH (machine-readable): grading type, languages, starter/solution
                    file lists, and test-case INPUTS + notes. No expected outputs (oracle rule).
  solution.cs     ← C#-specific: reference solution (the ORACLE, expected outputs are
                    GENERATED by running this, never hand-written)
  tests.md        ← human mirror of the hidden test cases (not parsed). MULTIPLE, VARIED,
                    with edge cases → resists hardcoding.
```

**Authoring rules proven/applied here**
- **Anti-hardcoding:** every problem graded by *multiple hidden test cases with varied inputs incl. edge cases* (zero, negative, large). `Console.WriteLine(7)` must fail. The general solution is the only thing that passes.
- **Oracle, not opinion:** expected outputs are produced by running `solution.cs`, not typed by a human.
- **Family, not 15 unrelated things:** the 15 problems are variations of ONE idea (numeric variables + choosing int/double), escalating difficulty, varied surface (context/type/values).
- **AI co-authors variations; the human + the running solution own the truth.**

## The ONE idea
Declare, initialize, and reassign numeric variables, and **choose `int` vs `double`** for a given value.

## Map / completion
1.3 is a **full drill section: 15 problems, lights at 9** (~60%). Per the course-wide rule, section size follows the idea's depth (floor 5, ceiling ~15) and completion is ~60% of the section's own count, so "8/15" is no longer a universal constant, it's just the shape of a full section like this one. The threshold is the authored `lights_at` field; the count is derived from the problem folders.
