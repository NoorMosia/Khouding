# 7.T, Chapter 7 Test (region boss)

The Chapter 7 region boss. It combines everything from 7.1 to 7.5 (resting on Chapters 1 to 6) into realistic
array scenarios. No new material is taught. Passing it lights the Chapter 7 region on the map.

## How it works
- **Pooled:** a single attempt draws **10** problems from the **20**-problem pool below. Passing **6** lights
  the region (~60%). A generous **24h** window; miss it or fall short and it simply does not light, a retry
  draws a fresh set. No lockouts, ever.
- **Non-memorizable, from both sides:** the pool is bigger than the draw, AND each pool problem reads an array
  from stdin, so it runs against several value-varied and length-varied inputs. Memorizing one attempt's
  answers does not survive the next draw, and a solution that hardcodes a result or assumes a fixed size
  cannot pass its own varied cases.
- Source of truth: `test.yaml`. Each pool problem is an ordinary problem folder under `pool/`; expecteds are
  generated by the oracle CLI from each `solution.cs`.

## Scope (same boundary as Chapter 7)
- **Input is used:** values come in via stdin in the **count-then-values** pattern (read `n`, then `n`
  values). 2D problems read the dimensions, then the grid row by row. `Main` drives the I/O; where a problem
  asks for a method, it is a `static` helper.
- **The full array toolkit from this chapter:** declaring and indexing (7.1), iterating with `for` and
  `foreach` (7.2), the operations sum / average / max / min / count / search (7.3), arrays as method
  arguments and the reference behaviour (7.4), and rectangular 2D arrays (7.5), on top of Chapters 1 to 6.
- **No `List<T>` or resizing** (Chapter 9), **no jagged arrays**, **no LINQ or `Array` methods** (write the
  loops).

## Anti-hardcoding: vary the contents and the length
This is the arrays boss, so the per-problem rule is the Chapter 7 one: each problem's cases **vary the array
contents and length**, including **length 0** where the operation is defined there (sum, count) and
**length 1**, so a solution that assumes a fixed size or hardcodes an answer fails. 2D problems vary **both
dimensions**, including a 1xk and a kx1 shape. **Every committed solution stays in bounds.** An array program
is deterministic per stdin, so the oracle `gen`/`check` work unchanged.
