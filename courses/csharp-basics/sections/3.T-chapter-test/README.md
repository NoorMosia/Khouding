# 3.T, Chapter 3 Test (region boss)

The Chapter 3 region boss. It combines everything from 3.1 to 3.5 (resting on Chapters 1 and 2) into
realistic compute scenarios. No new material is taught. Passing it lights the Chapter 3 region on the map.

## How it works
- **Pooled:** a single attempt draws **10** problems from the **20**-problem pool below. Passing **6**
  lights the region (~60%). A generous **24h** window; miss it or fall short and it simply does not light,
  a retry draws a fresh set. No lockouts, ever.
- **Non-memorizable, from both sides:** the pool is bigger than the draw, AND each pool problem takes stdin,
  so it carries several value-varied input cases (including negatives and edges). Memorizing one attempt's
  answers does not survive the next draw, and a hardcoded literal cannot pass a problem's own varied cases.
- Source of truth: `test.yaml`. Each pool problem is an ordinary problem folder under `pool/`; expecteds are
  generated by the oracle CLI from each `solution.cs`.

## Scope (same boundary as Chapter 3)
- **Input is used:** values come in via stdin. Prompts are printed on their own line, and the prompt text is
  part of the graded output.
- **The full operator set from this chapter:** precedence and parentheses (3.1), `/` with the
  integer-division rule (3.2), `%` (3.3), compound updates `++ -- += -= *= /= %=` (3.4), and the `Math` class
  (3.5), on top of `+ - *` from before.
- **No conditionals or loops** (Chapters 4 and 5).
- Negatives are included; overflow is not. Divide-by-zero and `% 0` are never fed.
- Decimal and `Math` output is deterministic under invariant culture; every such expected is CLI-verified.
