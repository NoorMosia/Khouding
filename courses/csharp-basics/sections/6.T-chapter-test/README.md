# 6.T, Chapter 6 Test (region boss)

The Chapter 6 region boss. It combines everything from 6.1 to 6.5 (resting on Chapters 1 to 5) into realistic
method scenarios. No new material is taught. Passing it lights the Chapter 6 region on the map.

## How it works
- **Pooled:** a single attempt draws **10** problems from the **20**-problem pool below. Passing **6** lights
  the region (~60%). A generous **24h** window; miss it or fall short and it simply does not light, a retry
  draws a fresh set. No lockouts, ever.
- **Non-memorizable, from both sides:** the pool is bigger than the draw, AND each pool problem takes stdin,
  so its method is called with several value-varied arguments. Memorizing one attempt's answers does not
  survive the next draw, and a method that hardcodes a single result cannot pass its own varied cases.
- Source of truth: `test.yaml`. Each pool problem is an ordinary problem folder under `pool/`; expecteds are
  generated by the oracle CLI from each `solution.cs`.

## Scope (same boundary as Chapter 6)
- **Input is used:** values come in via stdin. Prompts are printed on their own line, and the prompt text is
  part of the graded output. **`Main` drives the I/O and calls student-defined `static` methods; the methods
  compute (and sometimes print).**
- **The full method toolkit from this chapter:** defining and calling (6.1), parameters (6.2), return values
  (6.3), scope (6.4), and overloading (6.5), on top of types, input, arithmetic, decisions, and loops from
  Chapters 1 to 5, used inside method bodies and in `Main`.
- **No objects, instances, or fields** (OOP course) and **no arrays** (Chapter 7). Every method is a `static`
  helper in the `Program` class.

## Anti-hardcoding: vary the arguments
This is the methods boss, so the per-problem rule is the Chapter 6 one: each problem's cases call the method
with **varied arguments**, so a method that returns or prints a fixed answer fails. Branch- and loop-bearing
method bodies also follow the earlier edge rules (both sides of a condition, zero-iteration where a loop can
run zero times). A method program is deterministic per stdin, so the oracle `gen`/`check` work unchanged.
