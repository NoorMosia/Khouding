# 8.T, Chapter 8 Test (region boss)

The Chapter 8 region boss. It combines everything from 8.1 to 8.6 (resting on Chapters 1 to 7) into
realistic text scenarios. No new material is taught. Passing it lights the Chapter 8 region on the map.

## How it works
- **Pooled:** a single attempt draws **10** problems from the **20**-problem pool below. Passing **6** lights
  the region (~60%). A generous **24h** window; miss it or fall short and it simply does not light, a retry
  draws a fresh set. No lockouts, ever.
- **Non-memorizable, from both sides:** the pool is bigger than the draw, AND each pool problem takes stdin
  (or reads a provided file), so its output changes with varied inputs. Memorizing one attempt's answers does
  not survive the next draw.
- Source of truth: `test.yaml`. Each pool problem is an ordinary problem folder under `pool/`; expecteds are
  generated by the oracle CLI from each `solution.cs`.

## Scope (same boundary as Chapter 8)
- **Input is used:** most problems read **stdin** (a line, a count-then-lines shape, or a string plus a
  number/char). The **file-I/O family (F)** reads one provided, read-only asset file (staged at a fixed
  path like `data.txt`) and prints to stdout, grading is the usual stdout match (Flavor A).
- **The full string toolkit from this chapter:** measure & index (8.1), searching (8.2), transforming (8.3),
  split/join (8.4), char-by-char (8.5), and file I/O (8.6), on top of Chapters 1 to 7.
- **OUT:** `StringBuilder`, regex, culture-specific behaviour, `char` arithmetic, LINQ.

## Anti-hardcoding: vary the text and the inputs
Each problem's cases **vary the text** (content, length, empty, single char, mixed case, spaces) so a
hardcoded answer fails. The split/join family also varies word counts. The file-I/O family varies via stdin
(the provided file is fixed per problem). Every solution stays in bounds. The oracle is unchanged.
