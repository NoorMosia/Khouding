# Writing style (always applies)

This project has a strict, non-negotiable prose rule. It applies to ALL generated text: course content,
UI copy, documentation, and **Kiro spec documents (requirements, design, tasks)**.

## No em dashes. Ever.
- Never use the em dash character (U+2014) anywhere, including in spec documents you generate.
- Rewrite instead: comma, colon, parentheses, or two sentences.
- En dashes (`–`, U+2013) are allowed **only** for numeric ranges (e.g. `5–15`). Nowhere else.
- Before finishing any document, self-check for the em dash character and remove strays.

## Terse, concrete prose
- Problem statements and spec tasks: minimum words to be unambiguous. Prose is a cost.
- Readings: plain and concrete, anchored on something observable; no forced analogies.
