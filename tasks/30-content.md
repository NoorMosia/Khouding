# Content

> The spine. The route-map comes **before any code**, it's the cheapest way to find out if the whole thing is real (just writing + thinking), and it's the master document everything else mirrors.

## 1. C# course route-map `(CORE)`
- [ ] 1.1 Build the full table of contents **from the logic of C# itself**, independently (copyright-safe + better), not by walking any book's contents page.
- [ ] 1.2 Go to **section-level granularity** (section = the atomic unit: has a quiz, holds the problems, gets completed, shows on the map).
- [ ] 1.3 For each section, rough out: how many practice problems, and roughly what they cover.
- [ ] 1.4 Note which sections are hard-to-teach (so content effort is visible before building).
- [ ] 1.5 Decide chapter→region / section→landmark mapping for the course map.

## 2. Authoring format `(CORE)`
- [ ] 2.1 Define the structured, text-based, **AI-friendly** format for a section (reading, quiz, problems).
- [ ] 2.2 Define the problem format, must support both grading shapes:
  - [ ] "match this output" (stdin → expected stdout)
  - [ ] "pass these unit tests" (author test harness compiled alongside student code)
- [ ] 2.3 Define how **pre-seeded multi-file workspaces** are specified (which files exist, which the student edits).
- [ ] 2.4 Define quiz formats: true/false, multiple choice, fill-in-the-blank.
