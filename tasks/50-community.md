# Community

> Mostly `(LATER)` / north-star. One capability exposed many ways: **make the solitary act of learning visible and shared.** Do NOT build this before the core is proven.

## 1. Keystone, the stuck-problem share `(NEXT, first community feature)`
- [ ] 1.1 One-click snapshot: the problem + the code already in the editor, shared on-platform.
- [ ] 1.2 Answerable on-platform by: another student, or a paid human (1-1 tutoring). NO in-platform AI answer (see VISION §10b).
- [ ] 1.3 Public-by-default within a course → each solved thread becomes a resource for the next student.

## 2. Presence & opt-in visibility `(LATER)`
- [ ] 2.1 "N people working on this section right now."
- [ ] 2.2 Visibility is ALWAYS the student's choice, default private.
- [ ] 2.3 "Finished this section / open to helping" toggle → matchmaking + on-ramp to helper status.

## 3. Helper status & frontline `(LATER)`
- [ ] 3.1 Helper status rewards **quality** ("this solved it / was useful"), not volume.
- [ ] 3.2 Frontline warriors = standout members, ranked by contribution; **helping accrues the most points**.
- [ ] 3.3 Community badge (e.g. gold shield) shows on member profiles, group status flows to the individual.

## 4. The community world map `(LATER / north-star)`
> Distinct from the personal course map. Collective territory where groups stand among each other.
- [ ] 4.1 Groups as a general concept (university / department / bootcamp / club / city / country), don't hard-code "university".
- [ ] 4.2 Nested/fractal territories: Student → Department → University → City → Country.
- [ ] 4.3 Map **grows as communities emerge** (never an empty board).
- [ ] 4.4 Four separate axes: headcount (belonging, out of score), score (intensity not size), tenure (sticky-but-earned pioneer honour), frontline (individual honor roll).
- [ ] 4.5 Fairness: compare within a tier by intensity, not raw headcount.

## 5. Competition `(LATER)`
- [ ] 5.1 Opt-in, time-boxed events only, no ambient permanent leaderboards.
- [ ] 5.2 Territory campaigns (e.g. university vs university).
- [ ] 5.3 Local contests (lab-style, ephemeral), "problem-set + window + group", flavor A (speed/score race, reuses oracle grading); external physical prize, scoreboard-only, never a gradebook. First concrete consumer of the group entity (class = smallest group) and a seeding wedge. Full write-up + data-model sketch in `UXChanges.md` §8. Do NOT build before the core.
